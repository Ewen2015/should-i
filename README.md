# Ask Great Thinkers

用户丢进来一个决定，系统把它改写成一个能打分的命题，再拿这句话去问 **2578 个人**：
按你那套框架看这件事，你支持还是不支持。

每个人**正反两个方向各问一遍取中间**，得到 0–1 上的一个位置。2578 个位置按百年切开，
铺成一张世界地图、一根三色条、三张名单，和一句由这些数字现算出来的结论。

这个仓库是从 `should_i` 里切出来的第二个子产品。那一半（三个探针 + 一个判断）不在这里；
这里只有一件事：**把同一个问题问全人类，看它铺开成什么形状。**

## 运行

```bash
export TYPESAFE_API_KEY="..."   # Jev（也认 JEV_API_KEY / TYPESAFE_AI_API_KEY）
export DEEPSEEK_API_KEY="..."   # 只有一件事：把 X 说出来（也认 DEEPSEEK_KEY）
python3 server.py               # 然后打开 http://127.0.0.1:8420
```

纯标准库，没有依赖、没有构建步骤、没有数据库。key 只在这个进程里，
浏览器只跟 `/api/*` 说话。

不想碰终端的话，**环境变量可以不设**：起服务后打开页面底部的「设置 API key」，
把两个 key 粘进去，点「保存并测试」——它会各发一次真实请求告诉你到底通不通。

可选环境变量：`TYPESAFE_BASE_URL`、`TYPESAFE_DEFAULT_MODEL`（默认 `jev-latest`）、
`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`（默认 `deepseek-chat`）、
`SHOULD_I_JEV_CACHE`（缓存路径，设成 `0` 就整个关掉）、
`SHOULD_I_SETTINGS`（key 文件路径，测试用）。

```bash
python3 server.py --port 8420
```

> 如果这台机器有本地代理（Clash 之类），`http_proxy` 会把发往 `127.0.0.1` 的请求也拦下来，
> 看起来就像服务没起来。给自己配一个：`export no_proxy=127.0.0.1,localhost`。
> `smoke_test.py` 自己关掉代理，所以不受影响。

## 一次运行发生了什么

```
用户：人类要成为一个星际文明吗？
  │
  ├─ DeepSeek   把 X 说出来，并且对齐方向：
  │             「你支持人类成为一个星际文明吗？」＋ 同一句英文
  │             一次短请求，和下面 11 次 Jev 请求并行发出，所以不额外等它
  ↓
Jev ×11 批，每批 255 个人 × 正反两个方向 = 510 道 noul，一次请求
  │             老子 Laozi (571B–471B, China). On the user's decision,
  │             would he say: support it, or not support it?
  │             ＋ 把两个标签换个顺序、同时换掉 true 指哪一个，再问一遍
  ↓
每人的分数 = (正向 − 反向 + 1) / 2
  ↓
地图 / 三色条 / 文化圈 / 两头 / 三张名单 / 一句结论
```

一次提问 = **11 次 Jev 请求**，5,610 个判断，约 **38–41 万输入 token**，约 **19 秒**
（4 条并发）。同一句问题第二次是免费的，见下面「缓存」。

## 输入那一句必须被改写

`state` 里是读者原话，加上一句英文；**没有任何一道题说「it」是什么**。
这是省钱的必要条件，不是疏忽：决定写在 state 里一次，510 道题就都能指向它；
写进题面就是把它重复 510 遍。

但在这之前，X 是隐式的。「人类要成为一个星际文明吗？」本身既没说「支持成为」，
也没说是「支持还是反对成为」——而下面每一个数字都是「对 X 的支持度」。
所以有一次 DeepSeek 调用把 X 说出来：

- **方向必须是「做」的那一边。** 下游问的是「指向做还是不做」，
  而页面上「支持 X」显示成「做」。所以「该不该禁止短视频？」要写成
  **「你支持禁止短视频吗？」**，不能写成「你支持不禁止短视频吗？」——反了就是把 0 和 1 对调。
  这条写在 system prompt 里，也有测试守着。
- **形状要检查。** 一段散文会变成页面上的一整段话，一个**答案**会把产品的结论印在地图上面。
  `frame_en_ok()` 要求英文那行是一句话、以问号结尾、并且点名了 X
  （「Do you support it?」正是这一行要修掉的悬空代词）。不合格就退回只用原文。
- **原文照传。** 改写可以错，原文不会，所以两行都在 state 里；页面上改写下面是原话，
  小字一行截断。
- **它从不阻塞。** 改写没回来之前显示用户自己的话，DeepSeek 挂了就一直显示用户自己的话——
  退化的方向是「少一点帮助」，不是「空一行」。运行会等它最多 5 秒，因为英文那行必须在
  11 次付费请求之前拿到；拿不到就只带原文跑。

## 每个人是怎么被问的：只有身份，没有观点

发给 Jev 的每一道题，除了人名、生卒年、文化圈，**没有一句关于他想过什么**：

```
老子 Laozi (571B–471B, China). On the user's decision, would he say:
    support it, or not support it?     criteria {"true":"support it",...}
```

中英文名都留是有用的：英文维基是这个名录的来源，对 Kaṇāda、Kumārila Bhaṭṭa 这种人，
中文名单独拿出来是个更弱的抓手。

**那行「框架概括」是量出来该删的，不是偏好。** 原来每题都带一句
`老子（前571–前471，中国）的框架是：无为；不要强推，让事情自己落定`。
删掉它，平均每个人动 **0.0555**，是噪声地板（0.0061）的 **9 倍**，2613 人里 **627 人跨过 0.5**。
也就是说：那句话不是帮模型回忆的提示，**它就是被测量的东西本身**。

同一批实测还说明两件事：

| 第二轮怎么写 | r | 平均差 |
| --- | --- | --- |
| 重复这份名单 | 0.990 | 0.013 |
| 「上面那个人」 | **0.552** | 0.071（差 5 倍） |

所以每个人都被完整地重新点名一遍，哪怕同一个人在同一批里问两遍。
省这点 token 的代价是判断基本不可用。

## 为什么每个人问两遍

只问「它指向做还是不做」时，输出 **92% 说做**。听起来像个结论，其实里面混着
「模型更喜欢 `true` 这个选项」的倾向。反过来问一遍（把「不做」放在 `true`），取中间：

| 同一批 24 个框架 | 说「做」的比例 |
| --- | --- |
| 正问（`true` = 做） | 92% |
| **再问一遍同样的**（噪声底） | 88% |
| 反问（`true` = 不做） | 50% |
| **两遍取中间** | **63%** |

重复问同一句，`|A − A′|` 平均 **0.012**、最大 0.030；换个方向问，`|A − B|` 平均 **0.258**、
最大 0.720，24 个人里 **14 个的判断直接翻转**。噪声底和真实位移差一个数量级，
所以弯曲是真的。取中间是 `(正向 − 反向 + 1) / 2`：两遍读法一致时正好落在 0.5，
一个读不出方向的框架落在栅栏上，而不是被这个偏推到某一边。

## 为什么是 noul，不是 Choice

**Choice 的概率是和为 1 的帧内份额，不能跨批次相加。** 它问的是「这 255 个里**哪一个是**」，
是一次竞争：255 个选项里只有 3–6 个拿到概率，其余两百多个是 0。
**0 乘任何标定系数还是 0**——锚只能重新标定，不能把 0 救回成一个位置。
实测过：同样两组人加 12 个共同锚，两组之间的换算系数差 **4.1 倍**（0.29 vs 1.17），
根本不存在一个统一的系数。

**noul 是一句独立判断，不和同批的人竞争。** 同样 20 个人的框架，放进两个完全不同时代背景的
255 人名单里分别打分：

| | |
| --- | --- |
| Pearson r | **0.990** |
| \|最大差\| | 0.030 |
| \|平均差\| | 0.013 |

所以 noul 的分数天生跨批次可比，2578 个人可以切成 11 批分别问。

## 255 和 11 批

`255` 是 Choice/Noul 单次请求的硬上限。2578 个人 ÷ 255 ≈ 10.11，所以是 **11 批**。
每批正好 255 个选项，一批都不浪费；名录不足 255 时一批都不发。

**为什么不把名录做大。** 查得到的历史人物池子（英维条目 + 出生年，46 种职业）
一共约 **12,102 人**，是现在这 2578 人的五倍。12,102 位就是 **48 批**，一次提问约 55 万
输入 token，动画也有 48 段，用户看不到一半就会关掉。11 批是覆盖面和体验之间的折中。
真要全量，正确的做法是**两遍选择**（第一遍 255 个选项选「哪一段名单」，第二遍在那一段里排序）
——TypeSafe cookbook 里 `semantic_find.md` 写的就是这个模式。这一步还没做。

## 尺子上那 12 个人

既然要分 11 批发，就得把「各批可比」做成**每次都能当场量出来的数**，而不是一句承诺。

- **每一批正好 255 个选项**（243 个名录里的人 + 同样这 12 个锚），硬约定不破。
- **12 个锚出现在全部 11 批里**，所以同一个人在 11 个不同的「公司」里各被问一遍，
  他的 11 个读数的最大差就是真正的跨请求误差。
- **最后一批贴住现在**，因此和前一批重叠，重叠的人被两条不同的切片各测一次，
  是第二种、免费的交叉检验。重复测量**取平均**，不是后来者覆盖。

实测（一次完整运行）：

| | |
| --- | --- |
| 12 根锚跨 11 批的差 | 最大 **0.055**，平均 **0.021** |
| 重叠的人两次的差 | 最大 **0.025** |
| token | 约 38–41 万输入 / 12 万输出 |
| 用时 | **约 19s**，与动画并行，用户看不到等待 |

**加锚会不会把别人挤歪？** 这是这个设计唯一的真风险，所以单独量过：同一批 243 个古代人，
**单独问一遍** vs **把这 12 个锚塞进去再问一遍**——r **0.996**，平均差 **0.008**，
最大差 **0.030**。锚是校准而不是扰动，它占掉每批 12 个名额（约 5% 的成本）。

**这 12 个是默认值，不是设计。** 任何一组名录里的人都能当锚。标题栏上的
**「锚点 12 人」**按钮可以搜名字（中文、拼音、英文都行）换人；
「确认」只记下人选、不发请求，「确认并重跑」才会花那 11 次。

## 缓存

同一个端点对同一份输入几乎是确定的（原样重跑 r = 0.997、平均差 0.0061），
所以用 `(url, 请求体)` 做键的缓存**不会改变任何一次输出**，只保证同一句问题第二次不再付钱。
`jevcache.py` 就是它，两个上游的每一次调用都过它。

键是请求体本身，所以**换模型 = 换键，换 key ≠ 换键**——同一句问题问同一个模型，
答案是同一个，谁付的钱不影响这件事。它存在**另一个文件**（`should_i.jevcache.db`），
超过 64 MB 按最近最少使用淘汰。

三条它不许破的规矩，都在 `test_upstreams.py` 里：

- **失败永不入库。** 只有带 `answers`（Jev）或 `choices`（DeepSeek）的响应才写得进去。
  缓存一次超时，会把一分钟的网络故障变成永久答案。
- **命中必须报 0。** 原始数字挪到 `saved_input_tokens` / `saved_output_tokens`，
  调用方把 usage 相加得到的是**这次真的花了多少**。
- **连通性检查绝不走缓存。** 一个从磁盘上回答「有回应」的连通性检查，
  比没有检查更糟——它看着像证据。

这条同时关掉一整类「优化」：**重试、自我一致性、多问几遍取平均**。
这个端点没有采样噪声可以平均掉，重复调用买不到任何东西。

## 页面

- 进入后 **3-2-1 倒计时**（盖住头几秒的等待），然后开始扫描。
- **地图上面那行大字是改写过的，不是用户的原话**，下面小字是原话。
- 世界地图用 **Natural Earth 110m 陆地轮廓**（烤进页面），圆点才是真数据。
- **一格 = 一百年。** 整条时间轴 32 格（公元前 1100 到 2026，按去世年切），
  **最后一格是全部历史**。一格之内按去世年依次亮起。
  **粉 = 支持（≥0.60）、青 = 反对（<0.40）、灰 = 无所谓、暗灰 = 还没测到**，
  点的大小是**离 0.5 有多远**。
- **空的一格会说它自己是空的**：这一百年名录上没有人 / 还在等分数 / 拿到了分数但没回来，
  三种「没有」分开说。
- 地图下面是**三色条**（这一百年多少支持 / 无所谓 / 反对），再下面是**各文化圈**同一百年里
  的三色条，再下面是**这一百年的两头**（最支持的那个、最反对的那个，带维基链接）。
- **拖着时间轴，整页跟着走** —— 地图、三色条、文化圈、两头、三张名单和直方图。
  所以「17 世纪谁最支持」不需要第二次请求，就是同一批数字换了个切片。
- 面板里是**三张名单**（最支持 / 最无所谓 / 最反对）、**分数直方图**、以及
  **那 12 个锚落在哪儿**。同名地点会叠在一起，所以每个点按 id 做确定性抖动 ±2.2°。
- 结论是**每次重画时现算的**，不是从 Jev 直接拿的。人数少的时候它会说
  「这一百年只有 6 个人，构不成一个分布」，而不是把 5 比 1 报成「多数赞成」。
- 支持 / 无所谓 / 反对的**分档阈值**是 `TK_SCALE_HI = 0.60` / `TK_SCALE_LO = 0.40`，
  0.5 是「两遍读法一致」，不是「没意见」——页面上写明了这一点。
- 关闭 JavaScript 后页面打不开任何数据：这一页是纯前端渲染的，没有服务端预渲染版本。
- 支持深色模式（跟随系统）。视觉语言照 [typesafe.ai](https://typesafe.ai/)：
  ink `#1E1E1E` / paper `#FEFEFE` / 粉色 `#F386A1` 的抖动渐变天空条、Win95 风格窗口。

| 北美 | 270 | | 朝鲜半岛 | 24 |

- **来源**：671 位手写核心 + 1907 位 Wikidata 导入（要求英文维基条目 + 生卒年 + 出生地经纬度）。
  导入用的是 sitelinks ≥ 50 那条线，砍掉了长尾。
- **英文维基是偏向西方的，这一步会传染。** 西欧 + 北美 + 东欧占 **50%**。
  所以非西方文化圈用了更低的门槛（25–60 而不是 50–100）；不这么做，
  中国、印度、日本、拉美、非洲加起来会不到 5%。**这不是修好了，是被压住了**：
  想要一张真正平衡的地图，得再查 zhwiki / hiwiki 等其他语言版本。
- **抖动 ±2.2° 是视觉修正，不是地理精度。** 出生地数据本来也不支持更高精度。
- **在世的人都堆在「至今」这一年**，所以最后一帧是按出生年排的世代递进，
  但「谁和谁同代」仍然看不出来。
- 名录里每个人一句的 `frame` 字段还在数据里，但**不参与任何一次请求**
  （见上面「只有身份，没有观点」），页面上也没有展示它。

维基链接：2578 人全部有链接，**没有一个人是点不动的**。链接由 `thinkers.wiki_url()`
在服务端拼好，浏览器从来不用名字拼 URL。

## 已知的取舍

- **概率是帧内份额这条约定，现在没有活着的执行者。** 唯一会返回帧内份额的接口
  （11 帧 Choice 流）已经删掉了。地图、三色条、文化圈、两头、三张名单和直方图，
  读的全是 noul 那把尺子，而尺子一次判断不和同批的人竞争，天生跨批可比。
  规则留着，是因为任何一次「把 255 个人塞进一个 Choice、再拿它的概率当分数」的改动
  都会立刻把它踩响。
- **「全人类」是 2578 位有英文维基条目的人，其中一半来自西欧 + 北美 + 东欧。**
  所有历史那一格的结论是按人头汇总的，而名录在时间上的密度是维基条目的密度，
  不是人口的密度。这一条是这张图最大的解释性风险。
- **画面上是两位小数，但跨批次误差最大 0.055。** 单个人的 0.62 和 0.58 不是一个差别，
  而三张名单正好是读者会把它读成排名的地方。分档（0.60 / 0.40）比小数位更可信。
- **没有结果回填，也没有账号。** 这一页只读不写：没有数据库，没有历史，没有分享链接。
  同一个问题第二次运行是缓存命中，所以它其实是可复现的——但复现出来的东西没有地址。
- **`index.html` 里还有几条这个产品自己就没人用的 CSS**
  （`.tk-ramp`、`.tk-dots`、`section.view`），是从原仓库一起带过来的，没有顺手删。
